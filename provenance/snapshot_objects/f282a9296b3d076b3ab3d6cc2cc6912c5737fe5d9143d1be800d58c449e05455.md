# Similarity-selective Structure sweep

기존 `structure_multicenter_separation`, `structure_e3_followup`,
`structure_similarity_aware_followup`를 읽기 전용 의존성으로 사용하고 새 폴더에서만 구현한 실험입니다.

지원 protocol은 IA5, IA10, CAR5, CAR10이며 Stage 1은 protocol마다 C0 1개,
Method A 5개, B 9개, C 12개로 총 108 runs입니다. 기본 물리 GPU는 1번입니다.

## 환경 및 백그라운드 Stage 1 실행

```bash
cd ${RESEARCH_WORKSPACE}/structure_selective_similarity_sweep
source ${RESEARCH_WORKSPACE}/miniconda3/etc/profile.d/conda.sh
conda activate cds
mkdir -p logs

nohup ./run_all_similarity_sweeps.sh \
  --stage stage1 \
  --gpu 1 \
  --imageneta-root ${RESEARCH_WORKSPACE}/datasets/ptm_guided/imagenet-a \
  --cars-root ${RESEARCH_WORKSPACE}/datasets/ptm_guided/cars196 \
  > logs/stage1_gpu1.log 2>&1 &
echo $! > logs/stage1_gpu1.pid
```

Stage 1은 단일 GPU에서 수일이 걸릴 수 있습니다. 정확한 108-run 목록과 기존 실측 기반
예상 시간은 `experiment_queue.md`에 있습니다.

## 진행 확인

```bash
cd ${RESEARCH_WORKSPACE}/structure_selective_similarity_sweep
conda activate cds

python scripts/status.py
tail -f logs/stage1_gpu1.log
tail -f logs/stage1/IA5__C0__seed_1993.log
nvidia-smi -i 1
```

완료 run은 재실행 시 자동 skip됩니다. 중단된 run에 `checkpoint_latest.pt`가 있으면 자동
resume합니다. 각 run의 종료 코드는 `logs/stage1/exit_codes.csv`에 누적되고, 한 run이
실패해도 큐는 다음 run을 계속 실행합니다.

특정 protocol/run만 먼저 실행할 수도 있습니다.

```bash
python run.py \
  --protocol IA5 \
  --run-id A_P010 \
  --gpu 1 \
  --data-root ${RESEARCH_WORKSPACE}/datasets/ptm_guided/imagenet-a \
  --seed 1993
```

## Stage 2

Stage 1의 108개가 모두 끝난 후 guardrail을 적용해 protocol × method별 상위 2개를
동결하고 seed 1996/1997을 실행합니다.

```bash
python scripts/select_stage2.py

nohup ./run_all_similarity_sweeps.sh \
  --stage stage2 \
  --gpu 1 \
  > logs/stage2_gpu1.log 2>&1 &
echo $! > logs/stage2_gpu1.pid
```

## 검증과 보고서

```bash
python scripts/run_tests.py
python scripts/smoke_test.py
python analysis/build_report.py
```

스모크 테스트는 108개 config, 네 protocol의 실제 데이터 class 수/분할 및 공유 class
order를 검사하며 학습은 수행하지 않습니다. 큰 진단 테이블은 현재 `cds` 환경에 Parquet
엔진이 없으므로 동일 schema의 CSV로 정직하게 저장하고 `diagnostic_storage.json`에 이
사실을 기록합니다.

`analysis/build_report.py`는 실행 중 자동 요약을 `report_auto.md`에 쓰며, 검산된 상세
중간/최종 보고서인 `report.md`는 기본 동작으로 덮어쓰지 않습니다.
